# Product value — observed scope, not a live-agent claim

The isolated A–G harness exercises the production orchestration engine instead of
manually writing successful outputs into workflow records. Scoped patches, command
execution, approval gates, correction loops, snapshot-bound evidence and persistent
knowledge are real. Provider reasoning/implementation choices are deterministic
fixtures. This establishes mechanism behavior, not useful autonomous model judgment.

Observed benefits within that scope:

- A reviewer fixture that inspects actual files rejects a defect missed by deliberately
  weak initial acceptance, requests a concrete correction and verifies stronger tests.
- A deliberately faulty implementation triggers a real test failure and cannot complete;
  correction succeeds through the engine rather than manual file replacement.
- Documentation work resumes through fresh controller/provider fixture objects without
  replaying a completed patch; project instructions and verified memory survive reopening.
- Actual Chrome validates the frontend fixture before and after its scoped correction.
- The performance workload measures unchanged behavior and reduced computation on a
  controlled dataset; it does not infer model capability, general performance or cost savings.

Observed costs and limits:

- Every fixture uses explicit sharing/patch/command grants and multiple provider stages.
  Reported mock call counts expose coordination overhead, but no real tokens or human
  effort have been measured. The simplest useful live configuration is still unproven.
- Workflow history and checkpoints grow with retained evidence. The timed soak measures
  this growth rather than asserting leak-free operation. Its disposable full backups
  themselves create storage overhead; future harness runs now enforce explicit storage bounds, verified by a short smoke and guard tests.
- Actual browser verification required fixing custom automation races. Those failures
  are retained and must not be described as application defects or passed attempts.
- Retained QA evidence initially broke release packaging. Path redaction and a hygiene
  regression corrected that issue without relaxing the release security guard.

No conventional standalone AI baseline, memory-assisted standalone AI run, or live
multi-agent run has been authorized/executed for a comparable A/B/C benchmark. Real
input/output/cached/reasoning tokens, price-supported costs, model quality, false reviewer
approval/rejection rates, and reduced human intervention remain unknown. Do not convert
fixture call counts, byte estimates or scripted review success into those claims.

Phase 5 priorities, conditional on live pilot evidence:

1. Complete a small authorized Codex/MiniMax pilot and matched A/B/C runs before changing
   routing or context architecture. Preserve selected roles and exact session ownership.
2. Measure the cost of planning/review on small tasks; use existing single-task policy
   only where it preserves explicit acceptance and review requirements.
3. Preserve the corrected explicit-resume boundary: read-only planner/reviewer retry is
   allowed only with unchanged snapshots; uncertain effects need reconciliation. Measure relevant-context recovery and stale-memory behavior on related real tasks.
   Fix observed misses rather than adding speculative summarization infrastructure.
4. Measure long-history database/context latency and safe backup retention with explicit
   storage limits; preserve durable verification history.
5. Close the selected platform's installed-browser/credential/recovery acceptance,
   then separately assess other native platforms. No full-platform label from Linux alone.
